## 启动与第一次使用

### Docker / Compose

安装 Docker 与 Compose v2 后，在仓库根目录运行：

```sh
docker compose up --build --detach --wait
docker compose exec -T workbench cat /data/.local/login-url.txt
```

在浏览器打开第二条命令显示的私有登录链接。默认仅本机访问，数据持久化到命名卷；宿主机不需要安装 Python 或 Node.js。API Key 通过只读密钥文件提供，详见 [Docker 部署](docs/Docker部署.md)，含端口、密钥、备份、远程 SSH 访问与平台能力说明。

### Windows 直接启动

当前环境已安装、构建，并导入两个样例。双击 **`启动工作台.cmd`**，或者运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\启动工作台.ps1"
```

地址为 `http://127.0.0.1:8772/#cim`。启动器使用私有登录链接自动登录；凭证保存在 `workspace/.local/login-url.txt`，不要分享或提交该文件。Windows 直接启动方式没有 Docker 依赖。

项目标题下方的 **项目流程地图** 显示当前阶段、全部待办、推荐下一步和操作轨迹。可平移缩放、展开专家任务，点击节点查看输入、成果、阻塞原因并跳转现有表单；使用方法见 [流程导航](docs/流程导航.md)。

工作空间新增 **工作流**：逐阶段说明输入、责任、操作、产出、完成条件和返修交接。点击 **AI 协助创建**，可配置 DeepSeek 或兼容接口，由项目规划 Agent 对话整理需求，并预览、创建本项目专家、Skill、工艺包及待执行任务；详见 [项目规划 Agent](docs/项目规划Agent.md)。

迁移到另一台 Windows 电脑时，准备 Python 3.13 与 Node.js 22.14 或更高版本，运行 `安装与构建.ps1`；加 `-SeedExamples` 可导入当前目录旁的历史案例及合成 TT 演示。依赖锁定在 `app/requirements/factory-win-py313.lock.txt`，前端使用 `package-lock.json`。首次安装需联网下载依赖，日常厂内任务、解析、特征向量和索引在本机运行。

建议先打开 **“历史复盘 · 马达负载上报 FDC”**：

1. 在“资料与检索”核对四份输入/输出副本、哈希和资料用途。
2. 在“FDC / TT 工具”查看已保存的静态前后对照。需要重新分析时选择相应文件；注释 CSV 可通过 API 一并提供。
3. 在“项目概览”补齐实际点表、上报规范、纳入/排除通道及验收要求，再确认需求。来源文件变动会使旧任务过期。
4. 在“专家任务”按依赖创建执行批次，下载 ZIP，将其交给厂内批准的 AI，载入返回的 JSON；工程师审查后继续下一阶段。
5. 填写方案、BOM、人天及收益依据，分别登记编译、模拟、现场和效果证据，最后归档。

第二个项目 **“合成演示 · FA 产线 TT 改善”** 的所有事件均是合成数据，演示日志质量、瓶颈候选及完成数校准，不能作为现场收益证据。

每个角色有职责、输入输出、Skill、版本、工具权限、执行方式及成熟度。工艺专家按工段与设备关键词选择；Q/R 平台分别路由。无法确定设备时显示缺项。CF 等工段的 LUL/Conveyor 可以组合 FA 搬送专家。

当前专家分析的执行方式是 **厂内人工任务包交接**，并非后台已经连接了 34 个模型进程。可直接运行的确定性工具包括文件解析、检索、CSV 检查与对照、TT 数据核查、串行线 SimPy 仿真和费用计算。所有新专家、Skill 和工艺包仍标记 `candidate / field_validated=false`，需要真实设备资料及现场证据逐项发布。

## 业务闭环

```mermaid
flowchart LR
  A[CIM需求 / TT目标] --> B[资料与工程基线]
  B --> C[需求范围确认]
  C --> D[工艺 + 控制 + 改善专家]
  D --> E[方案 / BOM / 人天 / 收益]
  E --> F[候选程序与差异]
  F --> G[程序 + 工艺 + 证据审查]
  G --> H[编译 / 模拟 / 现场分别验证]
  H --> I[同口径前后对照]
  I --> J[归档 / 厂内案例复用]
```

一个业务项目可关联多个上游工程的明确版本。任务绑定项目输入版本、来源哈希、专家和 Skill 完整快照及执行批次。支持暂停/恢复、补充、返修、取消和重复回传幂等；旧输入回传保留为历史，不能完成新任务。重启后继续等待回传，不会自动重发模型请求。

## 数据与工程边界

- 原生 `.gxw` 路径保留在左侧“GXWorks 原生工程工作台”。CSV 是可选的只读分析、对照和候选文件交付路径；没有把 CSV 检查冒充原生编译。
- 原件按字节存储，候选文件另存。CSV 差异区分步号与其余列，包括指令、声明和注释。未知指令/绘图/语义覆盖依上游实际能力返回。
- 私有检索支持 Markdown/TXT/JSON/CSV/TSV/DOCX/XLSX/文本 PDF，返回文件 ID、哈希和行/页/表坐标。扫描 PDF、空文件及原生工程显示单独解析状态。
- 当前厂内索引是词项与 **128 维哈希特征向量**，不是已部署的预训练语义 embedding；没有自动下载模型。检索证据通过厂内任务 Agent 形成答案。
- 共享案例需先归档并由责任人批准，按相同工段、CPU 和设备类型匹配；案例撤回会使已使用它的活动项目任务过期。未实施的问题案例仍保留其实际结局。
- 资料分为 `pending/public/internal/restricted`。默认待分级；派生成果继承输入分级。任务包、检索、资料读取、归档和工厂 MCP 使用同一策略；外部目的地只允许 public。
- 后续专家任务仍使用厂内任务包。新建项目前置的规划 Agent 可单独配置 DeepSeek 或兼容 API，只处理本次输入的需求描述与内置能力目录；外部 API 仅接收 public 描述。工厂启动器不发布原生 MCP 凭证；上游工程模型任务仅允许明确关联、全部资料为 public 的工程。
