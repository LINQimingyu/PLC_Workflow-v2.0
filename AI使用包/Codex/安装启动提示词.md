# 安装与启动提示词

在 Codex 中打开本仓库根目录，将下面的内容作为本次任务发送。若只需要了解项目，改为“只读检查，不安装”。

```text
请在当前 PLC_Workflow-v2.0 仓库中安装并启动工作台。

先读取根目录 AGENTS.md、README.md 和 docs/Codex安装使用.md，确认工作目录包含 app/、安装与构建.ps1、compose.yaml。先检查当前操作系统、Python、Node.js、Docker 是否存在，以及是否已有工作台进程，保留原有工作空间和私有凭据。

Windows 本机优先使用现有 安装与构建.ps1，再用 启动工作台.ps1；不要导入私有历史案例。已安装时检查健康状态，不重复安装或覆盖数据。若本次选择 Docker，则按 docs/Docker部署.md 运行 Compose、检查健康状态及持久卷。

若缺少运行时，列出缺项及官方安装入口；仅在环境允许且我授权安装后处理。命令失败时读取真实错误并停止依赖该结果的后续步骤，不把文档里的历史检查结果当成本次验收。

安装或启动命令不需要调用模型。不要发起付费 API 请求或读取 workspace 内的真实业务资料。不要将登录 token、API Key 或登录链接写进回复、提交或日志；只告诉我登录文件在本机的位置。

验证 API 健康状态、前端可访问和数据目录后，报告实际成功项与未验证项。GX Works2 编译、模拟、硬件与现场验收未执行时明确保留待验证。
```

源码维护时，任务应明确要修改的行为；专家业务分析时，改用当前执行批次的任务包及共用回传提示词。不要把全部角色同时启动为并行 Agent。
