# 运行、数据和接口

## 数据目录

`workspace/business/factory.sqlite3` 保存业务记录、审计、原始文件 BLOB、带来源坐标的片段和本机哈希特征向量。`workspace/engineering/` 与 `engineering-state/` 属于上游工程服务。`workspace/.local/` 保存本机私有登录链接、进程标识、日志和隔离的上游模型设置。源码不存运行资料。

备份前停止本工作台进程，然后整体备份 workspace；不要只复制正在写入的 SQLite 主文件而遗漏 WAL。恢复整个目录后使用同一启动器，历史任务继续等待回传。当前面向单机、单工程师，不是多人身份/组织权限系统，也没有宣称数据库加密。

## HTTP

沿用上游回环地址、Host/Origin、操作员会话和 CSRF 保护。先 `POST /api/session` 提交启动器的 token，写请求提供同源 `Origin` 与会话返回的 `x-csrf-token`。不向外网监听。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/cim/catalog` | Agent、Skill 与工艺包目录 |
| `GET/POST /api/cim/projects` | 项目列表 / 新建 |
| `GET /api/cim/projects/{pid}` | 当前项目与历史任务、批次、结果 |
| `POST /api/cim/projects/{pid}/commands/{action}` | 共用业务命令 |
| `GET .../{pid}/search?q=...&include_shared=true` | 项目与已批准适用案例检索 |
| `GET .../{pid}/documents/{source_id}` | 按当前分级读取原始字节 |
| `GET .../{pid}/attempts/{attempt_id}/bundle` | 版本绑定任务 ZIP |
| `GET .../{pid}/archive-bundle` | 归档 ZIP |
| `GET .../{pid}/audit` | 审计轨迹 |

`action` 采用显式白名单：`update/confirm/document/classify/revoke/link/plan/start/submit/review/status/tt-analyze/csv-inspect/csv-compare/simulate/estimate/verify/archive/publish-case/withdraw-case`。实现与精确参数见 `app/src/cim/commands.py` 和服务方法签名。输入变更需 `expected_revision`；并发旧版本得到 409。

### 任务包合同

每次 `start` 提供稳定 `request_id`，重复请求返回同一批次。ZIP 含 `task.json`、完整角色/Skill 快照、来源文件、执行说明和 `return-template.json`。厂内 AI 回传 JSON 字段为：

```json
{
  "project_id": "从模板复制",
  "task_id": "从模板复制",
  "attempt_id": "从模板复制",
  "input_revision": 1,
  "snapshot_hash": "从模板复制",
  "summary": "结论与受限部分",
  "verdict": "candidate",
  "citations": [{"source_id": "资料ID", "sha256": "原始哈希", "location": "line:1"}],
  "questions": [],
  "findings": [],
  "artifacts": [{"name": "方案.md", "content": "候选成果正文"}]
}
```

结论只能是 `candidate/needs_info/failed`；AI 不能直接回传 approved。引用必须属于该输入快照，坐标必须真实存在。二进制候选通过资料入口上传，`kind=candidate`；验证原始文件以 `kind=evidence` 上传。回传本身不自动执行文件或脚本。

相同批次重复相同内容幂等，不同内容被拒绝。返修创建新批次，旧批次延迟结果只能进入历史。上下文超过 180 KB 时要求精简前置成果；不会静默截断指令或自动切换模型。当前使用保守的项目级输入失效策略，新增来源会使该项目全部现有任务过期。

### 验证和归档

人工验证 `phase=static/compile/simulation/field/benefit`，`status=passed/failed/not_run/not_applicable`。passed 必须附 evidence 来源、执行人及记录；系统保存人工声明，不伪造编译器或现场自动回执。not_applicable 必须说明理由，供证据审查。

实施归档检查当前需求确认、三个专业审查、静态/编译/模拟/现场记录；效果可以是 `pending_observation`。实测效果需当前 benefit 验证与原始数据。未实施和取消项目记录原因后也可归档。完整归档包含任务历史、估算、验证、对照、来源及审计记录入口。

## 工厂 MCP

原生工程 MCP 保持上游入口，不由工厂启动器自动向任何客户端发布凭证。新增工厂 MCP 是单独的、绑定一个业务项目的 stdio 服务：

```powershell
$env:PYTHONPATH = (Resolve-Path '.\app\src').Path
.\.venv\Scripts\python.exe -m cim.mcp --workspace '.\workspace\business' --project '业务项目ID' --trusted-internal
```

只有客户端和模型全程位于厂内时才配置 `--trusted-internal`。默认视为 external，仅能读取 public。示例连接配置采用绝对路径：

```json
{
  "mcpServers": {
    "tft-lcd-factory": {
      "command": "D:/path/PLC_Workflow v2.0/.venv/Scripts/python.exe",
      "args": ["-m", "cim.mcp", "--workspace", "D:/path/PLC_Workflow v2.0/workspace/business", "--project", "实际ID", "--trusted-internal"],
      "env": {"PYTHONPATH": "D:/path/PLC_Workflow v2.0/app/src"}
    }
  }
}
```

工具：`factory_catalog/factory_project/factory_search/factory_read_document/factory_read_task/factory_read_analysis`；厂内连接额外开放 `factory_submit_result` 和 `factory_run_tool`。后者须提供当前 `attempt_id`、稳定 `request_id`、工具名与参数，只允许角色快照中已经开放的 `plc.inspect_csv/plc.compare_csv/tt.analyze/tt.simulate/business.estimate`，并核对资料属于该批次快照。返回小型成果回执，再通过 factory_read_analysis 分页读取完整结果。重复相同工具请求复用结果；状态未明时拒绝盲目重跑。

不开放审查通过、项目归档、原生写入或在线 PLC 控制。客户端按 `next_offset` 接收分页并拼接 `json_chunk`，核对完整 SHA256，不能使用不完整上下文作为全部证据。

内网 URL 本身不证明模型在厂内；目前没有自动网络模型适配器。托管在本地的 MCP 服务连接外部模型仍属于外发，不能设 trusted-internal。以上是本工作台的资料边界，不能替代操作系统对其他软件直接读取文件的管理。
