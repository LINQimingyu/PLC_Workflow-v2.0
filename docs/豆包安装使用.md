# 给豆包使用本项目

这一方式提供项目知识、安装辅导及人工任务交接。工作台仍由本机 Windows 或 Docker 运行；本仓库不提供把 Web 服务、Windows 程序或 34 个后台进程托管进豆包聊天的功能。

## 准备材料

1. 下载公开的 GitHub 仓库，或使用已有本地项目。
2. 在仓库根目录执行 `python deploy/export_ai_usage.py --platform doubao`。只需 Python 标准库，不安装依赖、不连接模型、不读取 workspace。
3. 输出为 `.qa/ai-usage/PLC_Workflow-v2.0-豆包使用包.zip`。也可直接打开仓库 `AI使用包/豆包/开始对话.txt` 和 `AI使用包/共用/项目说明.md`。

说明包包含开始对话提示词、项目说明、34 个专家与 41 个 Skill 的目录、各方法正文、4 个候选工艺包说明及回传提示词。它不包含实际项目、登录信息或现场原件。

## 在豆包中开始

打开 [豆包官方入口](https://www.doubao.com/)，登录自己的账号，新建对话。先粘贴 `AI使用包/豆包/开始对话.txt`，再按需粘贴项目说明和目录。若当前界面支持文件上传，可上传解压后的相关文本；不要假定界面能读取 ZIP、私有 GitHub 或全部材料，也不依赖特定付费功能或上传额度。

先让豆包复述已读文件、项目边界和缺项，再选择安装辅导、需求整理或任务分析。安装辅导中，豆包提供步骤，工程师在自己的电脑执行并反馈真实输出。Windows 使用 `安装与构建.ps1` → `启动工作台.cmd`；Docker 见 [Docker 部署](Docker部署.md)。登录链接只在自己的浏览器使用。

## 做一次真实专家任务

1. 工程师在工作台确认项目范围、资料分级及当前版本，按任务依赖创建执行批次。
2. 只有可公开的项目和来源才可导出外部任务包。使用“豆包 / Codex 用包（public）”下载入口；后端会同时核对项目、合同、来源当前分级及撤销状态。厂内包不能直接上传豆包。
3. 将外部任务包解压；先给豆包 `INSTRUCTIONS.md`、`task.json`、`return-template.json` 与本任务需要的来源，再粘贴共用任务回传提示词。无法读取二进制原件时明确标记缺项，不让模型猜测文件内容。
4. 保存返回的纯 JSON 为 UTF-8 文件，在本机工作台“载入任务回传”中导入；工程师审查后接受或返修。没有真实批次时，不生成虚构 ID。

只为便于外发而把内部或待分级资料改成 public，不符合本项目的资料契约。对这类业务继续使用批准的厂内 AI。

## 验证范围

交付检查可确认说明包来源、条目数量、无运行资料，以及 external/public 导出和回传契约。未自动登录豆包、上传用户项目或调用豆包模型；豆包实际读取、回答质量和账号功能仍需使用者在当前客户端核对。
