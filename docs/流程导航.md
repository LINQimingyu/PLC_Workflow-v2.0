# 项目流程地图

打开业务项目，标题下方默认显示七阶段摘要和推荐下一步；各业务标签页共用相同流程状态。点击阶段或“展开地图”可查看完整流程图，“全屏查看”保留详细依赖导航。新版会保存本项目的展开偏好。

## 如何使用

1. 先看“最近完成 / 当前待办 / 推荐下一步”。推荐按钮会进入现有业务页面，提交与审查继续在原表单完成。
2. 画布默认以可读字号定位当前阶段。拖动画布、滚轮缩放，或用“适应全图”查看七阶段总览；“定位当前节点”返回当前位置。
3. 点击阶段查看右侧指引，使用“展开”显示本阶段任务；验证阶段有静态、编译、模拟、现场、效果五个子节点。
4. 点击任务查看谁来处理、所需输入、已有成果、完成条件及阻塞原因。“上一步 / 下一步”中的节点名称可继续点击查看依赖。
5. 点击“前往…”后，页面定位到对应任务、资料、验证阶段或成果记录。流程地图的查看与导航不会执行任务。
6. 展开“操作轨迹”回看真实操作，默认最近 20 条，可以加载更早记录。历史记录和当前版本进度分别显示。

专家任务页面采用列表与详情两栏。默认展示可处理任务，等待前置、已结束及历史任务可展开查看。点击任务后，在详情区载入回传文件并核对摘要；“查看 / 编辑回传 JSON”提供原始编辑入口。项目、任务、版本或执行批次不匹配时，界面暂停提交；载入与提交后仍须工程师人工审查。

“验证与归档”首先展示当前版本的静态、编译、模拟、现场及效果证据。点击对应的“查看 / 登记”进入原有登记表单，原始验证历史与归档记录继续保留。

虚线表示建议业务路线，实线表示任务合同中的真实前置依赖。选择某个任务后只突出其直接前置和后续关系；折叠阶段会作为该阶段任务的连线端点。当前阶段可以同时有多项待办。

## 状态如何理解

- 需求人工确认与需求专家任务是两项独立的事情；人工确认后，专家任务仍可能待处理。
- “等待厂内回传”表示批次已经创建，推荐操作是载入回传，而非重复创建批次。
- 回传进入审查后，经工程师审查通过才计入已完成任务；返修、待补充、失败、取消分别保留状态。
- 新来源、资料分级或工程基线变化会使旧任务过期；旧版本成果不计入当前版本完成数量。
- 验证只显示当前版本每项最新登记结果。“有理由豁免”与“通过 · 已登记证据”分别标注。
- 验证主阶段的完成数量是静态、编译、模拟、现场四项；效果单独显示，归档可以注明仍在观察。
- “归档专家成果”和“项目正式归档”分开显示。未实施或取消也能按原有规则归档，界面不会据此把之前阶段全部标成通过。
- 目前验证记录的来源是人工登记及其证据，不代表系统自动完成了真实编译或现场验收。

保存操作后刷新流程，页面重新获得焦点时也会重新读取。读取失败时保留有时间标注的旧快照，暂停推荐入口，并显示“状态未刷新”。旧审计没有记录执行人或版本时，显示“未记录”，不倒推补造。

## 本地接口

- `GET /api/cim/projects/{pid}/workflow`：在同一数据库读快照中计算当前节点、依赖、阻塞、推荐动作及归档结局。沿用现有操作员认证，不写项目或审计记录。
- `GET /api/cim/projects/{pid}/audit?limit=20`：最新操作轨迹，返回 `events` 和 `next_before_seq`。可传 `before_seq` 继续向前加载，`limit` 范围 1–100。
- 不传分页参数的原审计接口保持 `{"events": [...]}` 与原有正序行为。

流程数据从既有业务记录计算，不增加独立进度表，不迁移现有数据库。任务可执行条件、已实施归档检查与实际业务操作共用检查函数。图谱组件与资源打包在本地前端中。

在 `app/` 下运行：

```powershell
../.venv/Scripts/python.exe -m pytest evals -q
```

在 `app/web/` 下运行：

```powershell
npm test
npm run build
node tests/factory.e2e.mjs
node tests/workflow.e2e.mjs
```
